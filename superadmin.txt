1. РОЛИ
───────────────────────────────────────────

  super_admin  — полный доступ. Единственный: rem22p.
  admin        — сотрудники-управленцы. Не видят пользователей,
                 не могут создавать/удалять пользователей.
                 Полный доступ к товарам, категориям, профилю.

3. БЭКЕНД
───────────────────────────────────────────

  3.1 Новая middleware: internal/middleware/require_super_admin.go

      Аналог RequireAdmin, но проверяет role == "super_admin".
      Возвращает 403 если роль не super_admin.
      Использовать: requireSuperAdmin(getRole)(handler)

  3.2 Новый хендлер: DeleteUser (handler.go)

      DELETE /api/admin/users/{username}
      - Проверяет username из пути
      - Запрещает удалять самого себя (req username == path username → 400)
      - Вызывает store.DeleteUser
      - Возвращает 204 No Content

  3.3 Новый store-метод: DeleteUser (user_postgres.go)

      DELETE FROM users WHERE username = $1
      Если RowsAffected == 0 → ErrNotFound

  3.4 Обновить userStore interface (handler.go):
      Добавить DeleteUser(ctx, username) error

  3.5 Обновить маршруты (main.go):

      Было:
        adminOnly = authMW + RequireAdmin + adminCSRF

      Стало:
        superAdminOnly = authMW + RequireSuperAdmin + adminCSRF

      Применить superAdminOnly к:
        GET    /api/admin/users              (список)
        POST   /api/auth/register            (создание)
        DELETE /api/admin/users/{username}   (удаление)

      Остальные /api/admin/* маршруты остаются на adminOnly (обычный admin).
